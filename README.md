# 启德建材 · 微信销售小系统

给建材市场做的一个「微信里能用」的销售小工具：客户端看货、加购、出报价单、留手机号询价；
销售端看记录、改跟进状态、看数据。手机浏览器打开就是小程序的样子，不用装 App、不用 AppID。

## 一、跑起来

**双击 `run.bat`**，看到「已启动」后用浏览器打开：

```
http://localhost:8080
```

手机和电脑连同一个 WiFi，用电脑局域网 IP 访问（例如 `http://192.168.1.5:8080`），手机上就是完整的微信风格页面。

> 依赖：JDK 11 以上（我用的 JDK 22）。`lib/` 里已放好 sqlite-jdbc 和 slf4j，不用另外装数据库。

## 二、功能（v2）

**客户端**

| 功能 | 说明 |
|---|---|
| 商品浏览 | 18 条建材样例，分类筛选（瓷砖/卫浴/地板/板材/门窗） |
| 关键字搜索 | 搜名称和规格，例如「瓷砖」「马桶」「E0」 |
| 加入报价单 | 商品卡直接加减数量，底部购物车实时显示件数与合计金额 |
| 生成报价单 | 弹层列出商品明细 + 合计，可回看、可修改后再提交 |
| 提交询价 | 称呼 + 手机号（正则校验）+ 备注，报价金额随单入库 |

**销售端**

| 功能 | 说明 |
|---|---|
| 询价记录 | 按 全部 / 待联系 / 已联系 / 已成交 筛选 |
| 状态流转 | 每条记录可一键改状态，方便跟进不漏单 |
| 数据看板 | 在售商品数、今日询价、累计询价、待跟进数 |
| 咨询 Top3 | 按询价商品聚合，知道该备什么货 |

## 三、技术栈

- **后端**：JDK 自带 `com.sun.net.httpserver.HttpServer`（不装 Tomcat、不引 Spring）+ JDBC
- **数据库**：SQLite（`shop.db`，首次运行自动建表并写入 18 条建材样例）
- **前端**：原生 HTML + CSS + JS，微信绿 `#07c160`，移动端适配，`fetch` 调接口
- **零第三方后端框架**：后端 1 个 Java 文件，前端 1 个 HTML 文件

## 四、接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/products` | 商品列表，支持 `?cat=瓷砖`、`?kw=马桶` |
| POST | `/api/inquiry` | 提交询价（name / phone / product / remark / amount） |
| GET | `/api/inquiry` | 询价记录，支持 `?status=待联系` |
| POST | `/api/inquiry/status` | 改跟进状态（id / status） |
| GET | `/api/stats` | 商品数、今日/累计询价、待跟进、咨询 Top3 |

## 五、目录

```
启德建材-微信销售小系统/
├─ src/Server.java      ← 后端全部代码（路由 + 建表 + 接口 + 统计）
├─ web/index.html       ← 前端页面（样式 + 交互都在这）
├─ lib/                 ← sqlite-jdbc、slf4j
├─ run.bat
└─ shop.db              ← 运行后自动生成
```

## 六、面试怎么讲（三句话）

1. **需求从哪来**：建材老板的痛点是「客户在微信里问价，销售记不住、跟丢单」，所以做了个留资 + 报价 + 跟进的轻量工具。
2. **为什么这么写**：不用 Spring 是为了零部署——JDK 自带 HttpServer 起一个端口就能跑，老板电脑上双击就能用。
3. **有啥细节**：报价单金额随单落库、跟进状态三态流转、手机号正则校验、分类与关键字查询走同一条参数化 SQL、统计按天聚合。

## 七、自己动手改（面试官爱问“这行为什么这么写”）

1. 给商品加「品牌」「产地」字段，改表、接口、页面三处；
2. 加一个「导出询价 CSV」按钮；
3. 报价单加「运费」和「折扣」两个字段，合计要跟着变。

改完自己能讲清楚，再写进简历。
